# Introduction Version 2: Use Context First

`Use when the broad area is familiar and the opening should begin from a recognizable use context rather than a definition.`

```latex
% Start from a concrete setting readers recognize.
[Organizations/developers/users/researchers] increasingly rely on [computing artifact or practice] to [goal].

% Narrow to the problem.
However, [specific difficulty] prevents [desired property or workflow] because [technical reason].
```

## Concrete examples

HCI: `Software teams increasingly rely on collaborative dashboards to coordinate incidents across engineers, managers, and customer-support staff. However, these dashboards often present the same event stream to every role, forcing users to filter irrelevant information during time-critical decisions.`

Measurement: `Researchers increasingly rely on public package repositories to understand software supply-chain risk. However, repository snapshots mix active projects, abandoned packages, generated artifacts, and mirrors, making longitudinal conclusions sensitive to sampling choices.`

Theory: `Algorithm designers increasingly study online decision problems under resource constraints that reflect modern computing platforms. However, many analyses hide setup costs in asymptotic notation, making the resulting guarantees hard to compare when the number of requests is moderate.`
